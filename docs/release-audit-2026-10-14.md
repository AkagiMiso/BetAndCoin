## 本次修复

| 编号 | 问题与触发条件 | 修复和验证 |
| --- | --- | --- |
| R01 | Blackjack 消息注册未限制方向，会话包能够反向发送到服务端。集成服务器与客户端共用 JVM 时，不应允许这条路径修改客户端会话。 | 注册时限定手势包 PLAY_TO_SERVER、会话包 PLAY_TO_CLIENT；处理器在错误方向立即返回。两个回归测试确认不执行线程入队或修改会话。 |
| R02 | 当前玩家等待手势时，离线候补玩家被退款并清空座位，却没有立即将牌桌标记为需要保存。若此前状态已经保存，后续保存可能保留过期的预付记录。 | 周期离场检查处理座位后立即标记并同步。测试实际周期检查、一次退款、继续等待、保存更新标记及重复检查不重复退款。 |
| R03 | Blackjack 离场检查只判断在线、维度和距离，死亡但尚未重生的玩家仍可能保留座位；手势入口也未检查存活状态。 | 周期检查将死亡视为离场，手势处理拒绝死亡玩家。回归测试确认死亡玩家不能启动要牌。 |
| R04 | 独立的老虎机上半部没有方块实体，原版活塞可以推动上半部，破坏双格结构。 | 两个半部均使用 BLOCK 活塞反应。测试实际上下半部的反应。 |
| R05 | 轮盘下注和离线奖励合并仅比较物品类型，会将同一玩家不同名称或 NBT 的筹码合并，丢失其中一种物品的标签。 | 合并与显示清理同时比较类型和 NBT。测试不同名称的筹码分开结算、保持正确数量，并经过存档往返。 |
| R06 | 轮盘筹码的层间距为 0.35 模型像素，实际经过两层缩放后的厚度只有 0.144 模型像素，各层存在空隙。 | 使用实际 GROUND 变换计算基底与层厚。测试从真实筹码与桌面 JSON 读取尺寸，确认两种面额的五层筹码都接触桌面或前一层。 |

## 服务端运行检查

在临时目录的独立开发服务端、回环地址和独立端口进行启动检查，使用 ForgeGradle 源码运行环境：

1. 成功进入 Done 状态。
2. 创建 Blackjack、Farkle、轮盘、老虎机、喷泉、霓虹灯、桌面摆件、接待台八种主要功能方块，执行 save-all flush。
3. 使用最新源码重新启动同一隔离测试世界，强制加载对应区块；读取 Blackjack WAITING、Farkle WAITING、轮盘 IDLE、老虎机 Spinning=false、摆件 Variant=0。
4. 重载检查日志没有 ERROR、异常或服务端加载客户端类的错误。已发送 stop，日志确认保存并停止。

首次隔离启动设置被 ForgeGradle 覆盖，误启动了项目内原有的 run-server/farkle-test 开发测试世界，期间触发过自动保存。发现后已停止该进程，改用执行前明确设置 workingDir 的临时脚本，后续检查均在 tmp/release-audit-server。没有接入外部 Minecraft 客户端存档，也没有尝试回滚开发测试世界。

隔离世界首次创建时因空的超平坦配置出现过原版 DimensionGeneratorSettings 配置错误；重载前更正测试配置，最终启动日志无此错误。终端关闭时 Gradle 曾报告 daemon 消失；服务端日志已确认执行 stop 并保存世界，不能将该包装进程错误计为模组异常或构建通过。
